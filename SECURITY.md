# Security Policy

## Reporting a vulnerability

Please do not report security vulnerabilities through public issues.

Use a private security reporting channel available for the project, such as GitHub's private vulnerability reporting feature or a designated security contact.

When reporting a vulnerability, include:
- A clear description of the issue
- Steps to reproduce it
- Potential impact
- Relevant logs, screenshots, or proof of concept

Avoid including secrets or sensitive personal information in reports.

## General guidance

- Never commit passwords, API keys, tokens, private keys, or other secrets.
- Keep dependencies and tooling reasonably up to date.
- Review changes for accidental exposure of sensitive information.
